# 동작 규칙

앱과 서버가 계속 지켜야 하는 규칙. 규칙을 바꾸면 코드와 같은 PR에서 이 파일도 고친다. API 요청·응답 모양은 `openapi.yaml`이 기준이다.

## 주제와 노트 (1주차)

- 제목은 같은 주제 안에서만 유일하다. 미분류 노트끼리도 겹칠 수 없다.
- 주제 이름과 노트 제목에는 `/`를 쓸 수 없다 (이후 링크 표기 `[[주제/제목]]`의 구분자).
- 주제를 지우면 소속 노트는 미분류로 옮긴다. 미분류에 같은 제목이 있으면 삭제를 막고 겹치는 제목을 알려준다.
- 노트를 다른 주제로 옮겨도 `version`은 바뀌지 않는다. `version`은 제목·본문 수정에만 쓴다.
- 서버는 제목·본문을 NFC로 정규화해 저장한다. 이후 원문 구간(Span) 위치 계산의 기준이 된다.

## 수정 충돌 처리 (1주차)

같은 노트를 두 곳(브라우저 탭 두 개, 두 기기)에서 고칠 때 나중에 저장한 쪽이 먼저 저장한 내용을 말없이 덮어쓰지 않게 한다. 노트의 `version` 숫자로 검사한다 (낙관적 잠금).

```
서버 version 3
탭 A 저장 (version 3을 들고 옴) → 서버와 같음 → 저장, 서버 version 4
탭 B 저장 (version 3을 들고 옴) → 서버는 4 → 409 NOTE_CONFLICT + 서버의 현재 노트
```

### BE
- 요청의 `version`과 DB의 `version`을 **직접 비교**한다. 다르면 409 `NOTE_CONFLICT`를 돌려주고 `error.details.current`에 현재 노트를 넣는다.
- JPA `@Version`만으로는 부족하다. `findById`로 최신 행을 읽은 뒤 저장하면 앱이 오래된 version을 보냈다는 사실을 모른다. `@Version`은 비교와 저장 사이에 끼어든 요청을 막는 안전장치로 함께 둔다.
- 통합 테스트: 같은 version으로 두 번 저장하면 두 번째가 409.

### FE
- 저장 요청은 한 번에 하나만 보낸다. 응답을 기다리는 동안 입력이 들어오면 "저장할 내용 있음"만 표시해 둔다.
- 응답이 오면 받은 `version`으로 바꾸고, 남은 입력이 있으면 그 시점의 최신 내용으로 한 번 더 저장한다. (안 그러면 자기 자신과 충돌한다.)
- 409 `NOTE_CONFLICT`를 받으면 그 노트의 자동 저장을 멈추고 편집기 내용은 그대로 둔다. 저장 상태는 "저장 안 됨 · 충돌"로 표시한다.
- 1주차 충돌 화면: 알림 + "다른 곳의 내용 불러오기" 버튼. 비교 화면과 "내 내용으로 덮어쓰기"(현재 노트의 `version`으로 다시 저장)는 이후에 붙인다.
- 편집 중인 노트가 다른 곳에서 삭제되면 저장이 404 `NOT_FOUND`를 받는다. "다른 곳에서 삭제된 노트입니다"를 알리고, 편집기 내용은 지우지 않고(복사할 수 있게), 자동 저장을 멈춘다. "새 노트로 저장"은 이후에 붙인다.
